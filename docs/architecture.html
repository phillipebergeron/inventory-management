Data flow

Request lifecycle

  1. Filter change. The user changes Time Period, Warehouse, Category or Order Status in the FilterBar. State lives in the shared useFilters composable.
  2. Watch triggers load. Views watch the filters and call a method on api.js.
  3. HTTP request. Axios sends a GET to :8001/api/...; filters set to all are omitted from the query string.
  4. Filter in memory. FastAPI filters the lists loaded by mock_data.py.
  5. Validate & respond. Pydantic response_model validates and serialises JSON.
  6. Render. The view stores raw data in refs; computed properties derive chart and KPI values.

Startup & state

  1. uv run python main.py starts Uvicorn on 8001.
  2. mock_data.py reads every file in server/data/ once into module-level lists.
  3. npm run dev serves the SPA on 3000.
  4. Each request filters copies of the lists, so source data is never mutated. A restart reloads from disk.
  5. The only browser-side persistence is the chosen language in localStorage.

Observations

  • The API is read-only: CreatePurchaseOrderRequest and PurchaseOrder models exist, but no POST route uses them, and purchase_orders.json is empty.
  • Backlog.vue exists but has no router entry. Backlog data is only shown through the dashboard and its detail modal.
  • CORS allows every origin, there is no authentication, and the API base URL is hard-coded in api.js. Fine for a local demo, not for deployment.
  • Inventory has no time dimension, so the month filter does not apply to it.
  • The user profile (useAuth) is mock data. Large views such as Dashboard.vue (~1,270 lines) are candidates for extraction into components.
